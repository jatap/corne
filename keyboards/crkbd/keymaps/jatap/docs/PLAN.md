# PLAN.md — the plan behind `tools/layer_tables.py`

Status: **implemented for deterministic table generation, source annotations, firmware correspondence and targeted manual-review reports**. This is the design record for `docs/tools/layer_tables.py`, `docs/FORMAT.md`, the eight layer files in `docs/` and the `/layers` prompt. It is kept because it records _why_ each rule exists and which measurements set each number. Section numbers are the plan's own, so old notes that cite "D5" or "V7" still resolve.

For the rules themselves, read `docs/FORMAT.md`. This document does not restate them.

## 1. Mission

Make the layer reference survive being generated by different models. Not "make it pretty" — make the output deterministic despite the model. The plan's own summary of the problem:

- The same prose instructions produced different column widths on different runs and different models. Source padding is not rendered width: `pi`'s table renderer recomputes columns from content, so an aligned source table can still render ragged.
- Unfenced bordered tables were damaged by three independent things: Prettier reflowing an unpadded border into the first column, `pi` absorbing a bottom border as a table row, and GFM treating the whole box as a table it could stretch.
- Prose rules could not prevent any of it. A script could, because a model that ignores an instruction still has to pass a failing `check`.

The implemented design follows from that one inversion: **the script owns generated content and layout, while `/layers` only runs it and reports the result.** Firmware defines positions, keys and chords. Strict source annotations define macro effects. Application behaviour that cannot be proved cheaply is reported for manual review rather than guessed.

## 4. Locked decisions

D1. Every table is wrapped in a ` ```text ` fence. Evidence: Prettier does not modify fenced content (verified by round-tripping all nine files, zero bytes changed), `pi` and `glow` render fenced content verbatim, and the fence removes the contradiction between "this is GitHub Flavoured Markdown" and "this is a hand-built ASCII box". Cost: GitHub shows a code block instead of an HTML table, accepted knowingly.

D2. Two table shapes exist, key and graph, plus a combos table in `base.md`. `FORMAT.md` carries the worked examples.

D3. Command chords retain their modifiers in `Key`, `Chord` and graph cells. `HYPR(kc)` and `MEH(kc)` use their QMK names instead of expanded modifier chains. Graph abbreviations may shorten a key name, such as `Ctrl+Numpad Minus` to `Ctrl+Minus`, but never remove the modifier.

D4. `RCAG` and `RSAG` were to be documented as reserved notation. **This decision was wrong and was dropped**; see the corrections section.

D5. Literal `` ` ``, `\` and `|` replace the words `Backtick`, `Backslash`, `Pipe` and the `\|` escape in `Key`, `Chord` and graph cells. Only safe because of D1.

D6. `Does` prose names a character in lower case instead (`Types backtick`), because there it is naming the character rather than showing it.

D6b. Width cap 140 columns, set by measurement, not taste. See section 7b.

D7. One script owns all padding.

D8. The graph gap column is the constant `5`. Prose said "keep its existing width", which is undefined for a file that does not exist yet, and the real files had already drifted to two different values.

D9. The contract lives in `docs/FORMAT.md`, with one pointer line in `AGENTS.md`.

D10. Prompt testing happens in a `/tmp` sandbox copy, never against the real `docs/`.

D11. Every `Position`, `Key`, `Chord` and graph cell, every macro `Does`, and every combo row is generated. Deterministic templates generate ordinary key effects. Existing application claims are preserved only for direct shortcuts that have no source annotation.

D12. Strict one-line `@emacs`, `@niri` and `@system` annotations in `macros.c` are the authority for macro `Does` cells. The annotation payload is copied exactly. In the mixed-consumer Apps layer, the generator adds the consumer prefix.

D13. Missing, empty, duplicate or unknown annotations and unsupported firmware syntax are hard failures. An unsupported application interpretation is a review item, not an invitation for the generator or model to guess.

D14. A save resolves and validates every requested document in memory before replacing changed files atomically. `REVIEW REQUIRED` may write deterministic source-owned updates, then exits 2 with one consolidated report. A hard failure exits 1 and writes nothing. Check mode performs the same generation and byte-compares the result without writing.

D15. `/layers` is an orchestrator. It runs the deterministic generator, runs the final source-aware check after writes, and reproduces the generator's structured review or failure report verbatim.

## 7b. Why the cap is 140

Chosen from the real session rather than a guess. `TIOCGWINSZ` on the pty that `pi` runs in (a herdr pane inside kitty) gives 155 columns; the outer window is 175. Minus a column or two of `pi` chrome leaves about 153 for rendered content, and `pi` indents a fenced block by 2 columns. So the cap plus 2 must fit in about 153, which 140 does with 11 columns of slack.

Two numbers that are easy to get wrong later:

- `pi` adds 2 columns to a fence, `glow` adds 4. `glow` is the tighter budget: a 140-wide table wants a 144-column terminal.
- Today's widest table is 131 (`apps.md`), which renders at 133. Column width is set by the longest cell, so in the widest files a single long `Does` cell drives the whole table. If a future generation trips the cap, shorten that cell — never a header name, never by wrapping a cell across lines.

Rejected: renaming `Position` to `Pos.`, which saves 4 columns on all eight key tables. It buys nothing under a 140 cap, and it trades a self-documenting header in eight files forever for width that is not scarce.

## 11. Evidence worth keeping

- `quantum/quantum_keycodes.h:61-62` define `HYPR(kc)` as Ctrl+Alt+Shift+Super and `MEH(kc)` as Ctrl+Alt+Shift, so the notation is firmware vocabulary rather than something invented for the docs.
- Firmware and docs agreed exactly: 21 `HYPR(` and 4 `MEH(` in the sources, 21 and 4 expanded chains in the docs, which made the rename mechanical.
- The only modifier sets of three or more anywhere in the keymap or its docs are those two.
- `render_pi.js` was validated against both controls before being trusted: the unfenced files at 160 columns all failed with 49 unfenced table lines and an absorbed border row; the fenced versions all passed. A test that cannot fail is not a test.
- Emacs markup hiding eats unfenced backticks and backslashes and shifts the row, which is what proved the fence was doing real work. Dropped from the requirements afterwards, because the owner does not use that mode on these files.

## Corrections found while implementing

Six places where the plan was wrong. Each was verified before being written down.

1. **D4 was false.** QMK defines `HYPR`, `MEH` and `LCAG` (Ctrl+Alt+Super); there is no `RCAG(kc)` or `RSAG(kc)` macro anywhere in the tree. The README therefore defines `HYPR`, `MEH` and names `LCAG` as QMK's other three-modifier macro, unused here. Reserving notation that does not exist would have been a trap for the next reader.
2. **"ASCII only, anywhere" was too broad.** The first checker failed an em dash in a `FORMAT.md` heading. Wide characters only matter where they break column alignment, so the rule is now box-drawing characters anywhere, non-ASCII inside a table fence.
3. **`Key`/`Chord` duplication needed a rule, not prose.** V7 caught a model writing `Chord = HYPR+C` with `Key = C` and passing every existing check. A later review found the same loss in generated control chords: `LCTL(KC_0)` became `Key = 0`, and its graph also dropped `Ctrl`. `source_key()` and `check_semantics()` now preserve command modifiers. Shifted printable symbols remain represented by the resulting symbol.
4. **A single-consumer layer file does not name its consumer in `Does`.** `emacs.md` prefixed all 17 rows with `Emacs:`, which repeats the heading on every line. The prefix stays where it carries information, i.e. `apps.md`, whose rows point at Niri, Emacs and Kitty.
5. **Treating M20's uppercase event as intentional was wrong.** `SS_LALT("G")` emitted `Alt+Shift+G`, and Emacs happened to recover it through uppercase fallback before resolving `M-g g` to `goto-line`. Proving that fallback worked did not make the extra Shift correct. M20 now uses `SS_LALT("g")` and directly emits `Alt+G, then G`; the generator has no M20-specific translation exception.
6. **A layout-only check was not an acceptance test.** After M24 and M25 moved from Apps to Emacs, stale Apps rows still passed `check` because their borders, vocabulary and internal semantics were valid. The normal `check` now parses every recognised layer grid, derives `HOME_*` and `LAYER_*` aliases from `keycodes.h`, and compares both the detailed `Key` column and graph with firmware. `--no-source` is restricted to isolated fixtures.

V0 checker rejects all eight deliberately broken tables with a message each; passes good input. ## V7, the end-to-end prompt test

`pi -p -a --model deepseek/deepseek-v4-flash "/layers <layer> --save"` in a copy of the keymap under `/tmp`. Print mode never shows a trust prompt and silently skips untrusted project resources, so `-a` is required for the project prompt to load at all.

It earned its place. First run: the model wrote `Chord = HYPR+C` and `Key = C`, and every check passed — because the prompt's own `Key` bullet said "the base key" and no rule tested the duplication. After correction 3 above, a from-scratch run with `docs/apps.md` deleted (the harsh mode: contract and prompt only, nothing to copy) produced 36 rows with identical positions and identical `Key`/`Chord` pairs to the hand-made file, the numpad keys shortened to `Ctrl+Minus`/`Ctrl+Plus` in the graph, the resulting footnote emitted, and `check` exiting 0. Only `Does` prose differed, which is legitimate re-derivation and not a failure.

Read that as the standing result: **a different model on a different provider reproduces these tables.** Re-run V7 after any change to the script or the prompt, in `/tmp`, never against the real `docs/`.

## 12. Complete content generation

### Scope and implementation shape

`docs/tools/layer_tables.py` owns generation and checking without another framework or dependency. It reads `keymap_colemakdh.c`, `keycodes.h`, `macros.c` and `combos.c`. Grid tokens determine `Position`, `Key` and graph labels. Macro bodies and combo definitions determine canonical `Chord` values. Fixed templates cover characters, modifiers, layers, media keys and bootloader actions.

The macro comments are structured metadata rather than informal hints. Each `QMK_M*` case has one or more one-line annotations using `@emacs`, `@niri` or `@system`. The payload after the tag is copied exactly into `Does`; the Apps layer adds the target prefix because it mixes consumers. Empty, duplicate and unknown tags are errors. `@system` covers effects such as `Types the pound sign via Linux text input` that are not owned by one application.

Direct application shortcuts such as `HYPR+Q` have no macro annotation. Their existing human-reviewed claim is preserved. A new direct shortcut without a claim is generated as `Review required` and appears in the final report. This is the deliberate boundary: generation guarantees that documents match firmware and source annotations, but it does not claim to emulate every application's runtime.

### Chords and application evidence

`Chord` always records host-visible QMK output. The parser expands the narrow `SEND_STRING`, `SS_TAP` and `tap_code` forms used here. Its character mapping follows the QMK source pinned at `860fb36b130f6421784ac248b990f2063199b6c2`, including the Shift added for uppercase ASCII. M20 deliberately uses lowercase `g`, so its emitted chord is directly `Alt+G, then G` rather than relying on Emacs to repair an unintended Shift.

Application interpretation is evidence, not an authority that can rewrite an annotation. Unsupported or context-dependent interpretation is left for manual review. This is intentionally narrower than the rejected full Emacs, Niri and Kitty emulators, whose complexity and false-negative risk exceeded their value for these personal documents.

### Outcomes and reporting

`PASS` exits 0. `REVIEW REQUIRED` exits 2 and prints one consolidated report; write mode has already applied the validated deterministic update, while check mode remains read-only and may be comparing a stale document. `FAIL` exits 1 and writes no document. In check mode, source drift without a review item also exits 1. All requested outputs are derived and validated in memory before any replacement starts. Each replaced file uses a temporary file in the same directory followed by `os.replace`.

A review item gives the layer, position, macro or key, source path and line when available, raw QMK chord, previous `Does`, generated `Does`, and review class. Items are ordered by layer and physical position. Source-annotation differences and missing application claims require review; malformed annotations and unsupported firmware syntax are hard failures.

### Commands and update flow

`generate --write <layer|all>` regenerates documents. `generate --check [<layer|all>]` generates in memory and compares bytes without writing. `format` remains a layout-only repair command. The normal `check` verifies layout, `Key`, graph, every `Chord`, and every macro `Does` against source.

`/layers` only invokes these commands. It never writes a cell, edits firmware or application configuration, or resolves a warning itself. After a successful write it runs the source-aware check. If generation requires review, the prompt reproduces the script's one report verbatim.

### Tests and acceptance

Fixture tests cover source-position drift, literal pipes, annotation parsing, uppercase Shift conversion, nested modifier output, `tap_code` sequences, macro `Chord` and `Does` drift, missing application claims, review-report context, expanded final-cell formatting, combo extraction, and byte-identical generation of all eight repository documents. Final acceptance also requires a second zero-difference generation, normal source-aware checking, V7 in `/tmp`, whitespace checks and a clean firmware build.

## Scratch assets, not part of the repo

`/tmp/corne` holds the throwaway harnesses this plan used: `render_pi.js` (the `pi` render checker), `mtest.el` (the Emacs markup-hiding probe), `proto-*.md` and `f-fix-*.md` fixtures, sandbox copies. They are not versioned and will not survive a reboot. The repo owns the durable part: `docs/FORMAT.md` states the contract, `docs/tools/layer_tables.py` enforces it, `check` is the standing test. Rebuilding the render harness means writing a small script against `@earendil-works/pi-tui`'s `Markdown` class again — note that a `Proxy` theme breaks code blocks, because the optional `highlightCode` member must be absent rather than identity.

## Known gaps and follow-ups

- The generator verifies that macro documentation matches source annotations; it does not prove that every annotation remains correct in its target application. The review report makes that boundary explicit.
- Direct application shortcuts in `apps.md` and `niri.md` retain their existing human-reviewed claims. Adding source annotations for non-macro shortcuts would require a separate metadata design and is not needed now.
- The broad hostile-input V0 fixtures remain in `/tmp`. The permanent suite now covers source drift, literal pipes, malformed annotations, emitted macro events, review output and repository-wide generation.
